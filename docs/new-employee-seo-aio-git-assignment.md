# 新社員向け課題: Gitを用いたSEO・AIO対策実装

## 1. 課題の目的

この課題は、pardesのコーポレートサイトを題材に、次の2点を実践的に身につけることを目的とします。

- Gitを使った基本的な開発フローに慣れること
- SEO・AIO対策を自分で調査し、実際のWebサイトへ反映できるようになること

単にコードを変更するだけでなく、「なぜその実装がSEO・AIO上有効だと判断したのか」「どのファイルのどこを変更したのか」を自分の言葉で説明できる状態を目指してください。

## 2. 対象リポジトリ

- 対象サイト: pardes コーポレートサイト
- 技術構成: Next.js / TypeScript
- 参考資料:
  - `README.md`
  - `docs/specs/pardes-corporate-site/aio_seo_geo_llmo_strategy.md`
  - Next.js公式ドキュメント
  - Google Search Centralなど、SEO・構造化データ・AIOに関する信頼できる一次情報

## 3. 対象企業とサイトの目的

SEO・AIO対策では、検索エンジンや生成AIが「このサイトは何の会社の、何を説明する公式情報なのか」を正確に理解できる状態にする必要があります。実装前に、以下の前提を必ず把握してください。

- 社名: `pardes`
- 代表者の目的: `binet` と呼ばれるAGIおよびSDKを開発者に提供するため、技術・製品・会社の存在を広く伝えること
- サイトの目的:
  - `binet` / AGI / SDKの認知を広げる
  - 開発者・技術者に対してSDK利用や問い合わせのきっかけを作る
  - pardesという企業の公式HPとして、会社の信頼性を伝える
  - エンジニア採用につなげる
- 主な想定読者:
  - AGI、AI SDK、AIエージェント、ロボティクス、ニューラルネットワークに関心のある開発者
  - SDK導入を検討する企業の技術責任者・研究開発担当者
  - pardesへの応募を検討するエンジニア

この課題で行うSEO・AIO対策は、単に検索順位を上げるためではなく、検索エンジンや生成AIが次のように理解・引用できる状態を目指すものです。

```text
pardesは、binetと呼ばれるAGI/AI SDKを開発者向けに提供しようとしている企業である。
このサイトは、binetの概要、企業情報、問い合わせ先、採用情報を確認できる公式サイトである。
```

ページタイトル、meta description、見出し、本文、構造化データ、OGP、`llms.txt` などを確認するときは、この前提と矛盾していないかを必ず確認してください。

## 4. 必須のGit作業

以下のGit操作を必ず自分で行ってください。

1. "https://github.com/kaduiro/pardes-hp"にアクセスし、クローンする
2. 作業用ブランチに移動（ブランチ名：feature/toshiki/AioSeo）
3. サイトのSEO・AIO改善を実装する
4. 変更内容をステージングする
5. コミットする
6. リモートリポジトリへプッシュする
7. Pull Requestを作成する


コミットメッセージの例:

```bash
feat: AIOとしてjson-ldをHomeに追加
```

## 5. 実装課題

このサイトに対して、SEO・AIO対策を実装してください。

ただし、基本的な確認観点以外の具体的な実装内容は、すべて自分で調べて判断してください。既に実装済みの項目がある場合は、その妥当性を確認し、改善できる点を探してください。

最低限確認する観点:

- 各ページのtitleとmeta descriptionが適切か
- 社名 `pardes`、製品名 `binet`、AGI、SDK、開発者向け提供、エンジニア採用というサイト目的が、主要ページで機械的に理解できるか
- OGP / Twitter Cardなど、SNS共有時の情報が適切か
- `sitemap.xml` が主要ページを正しく含んでいるか
- `robots.txt` が検索エンジンやAIクローラーに対して適切か
- 日本語・英語ページの多言語SEO設定が適切か
- 見出し構造、画像のalt、リンクテキストが機械的に理解しやすいか
- JSON-LDなどの構造化データが、ページ内容と矛盾していないか
- AIOや生成AIに引用されやすい、明確で抽出しやすい文章構造になっているか
- 採用ページが、エンジニア採用を目的としたページであることを検索エンジンや生成AIが理解できるか

調査して追加検討してほしい観点:

- AIO、GEO、LLMOで重視されるサイト構造や文章構成
- schema.orgの適切な型
- Google Search Centralの最新推奨事項
- AIクローラー向けの情報整理方法
- 競合・類似企業サイトのSEO/AIO上の工夫
- Core Web VitalsやアクセシビリティがSEOに与える影響

## 6. サイト外で必要になるSEO・AIO施策

SEO・AIO対策には、このリポジトリ内のコード変更だけでは完結しないものがあります。今回のPull Requestでは、実際に外部サービスを操作できない場合でも、以下の施策について「必要性」「実施手順」「現時点での未対応理由」をPull Request本文に整理してください。

| 施策 | 理由 | やり方 | 今回の課題での扱い |
| --- | --- | --- | --- |
| Google Search Console登録 | Google検索での表示状況、インデックス状況、検索クエリ、サイトマップ送信状況を確認するため | ドメイン確定後、Search Consoleでプロパティを追加し、DNS認証またはHTMLタグなどで所有権を確認する。その後、`/sitemap.xml` を送信し、インデックス状況と検索パフォーマンスを確認する | 実操作できない場合は、PRに登録手順と必要な環境変数・確認コードの扱いを書く |
| サイトマップ送信 | Googleが主要ページを発見しやすくし、送信後の処理状況を確認できるようにするため | Search Consoleのサイトマップ画面から `https://本番ドメイン/sitemap.xml` を送信する | `app/sitemap.ts` が正しく出力するかをローカルで確認し、送信手順をPRに書く |
| URL検査とインデックス登録リクエスト | 重要ページがGoogleにクロール・インデックスされているか確認するため | Search ConsoleのURL検査でトップ、会社概要、製品、採用、お問い合わせなどを検査し、必要に応じてインデックス登録をリクエストする | 対象URL候補と確認観点をPRに書く |
| Google Analytics / GA4確認 | 検索流入後のユーザー行動、採用ページや問い合わせ導線の成果を確認するため | GA4プロパティを用意し、計測IDを環境変数に設定する。ページビュー、問い合わせ導線、採用ページ閲覧などを確認する | 既存実装の有無を確認し、未設定なら必要な設定項目をPRに書く |
| 被リンク獲得 | 外部サイトからの自然な言及により、検索エンジンと生成AIがpardesの信頼性・関連性を判断しやすくするため | 代表プロフィール、登壇資料、技術ブログ、GitHub、採用媒体、プレスリリース、提携先・研究機関ページなどから、文脈のある自然なリンクを得る | 購入リンクや不自然な相互リンクは避ける。候補媒体、掲載理由、リンク先URLをPRにリストアップする |
| GitHub / npm / SDK配布ページからのリンク | `binet` をSDKとして開発者に届ける目的と、公式サイトの関連性を強めるため | SDKリポジトリ、README、npmパッケージ、ドキュメントサイトがある場合、公式サイト・問い合わせ・採用ページへのリンクを設置する | 現時点で対象リポジトリが不明な場合は、設置候補とリンク文言案を書く |
| 技術記事・解説記事の公開 | AIOでは、固有で有用な技術説明が引用候補になりやすいため | `binetとは何か`、`AGI SDKとして何を提供するのか`、`開発者が何を試せるのか` など、検索意図に答える記事を公式ブログや技術ブログに公開する | このサイト内に追加すべきページ案、外部媒体に出す記事案をPRに書く |
| 採用媒体・SNSプロフィール整備 | エンジニア採用目的のサイトであることを外部接点からも伝えるため | Wantedly、LinkedIn、X、採用媒体、代表プロフィールなどに公式サイトと採用ページへのリンクを設置し、表記を統一する | 表記ゆれが出ないよう、社名 `pardes`、製品名 `binet` の推奨表記をPRに書く |
| リッチリザルト・構造化データ検証 | 構造化データが検索エンジンに正しく読まれるか確認するため | GoogleのRich Results TestやSearch Consoleのレポートで、JSON-LDのエラーや警告を確認する | ローカルまたはデプロイURLで検証できる範囲を確認し、結果をPRに書く |

外部施策を調査するときは、短期的に順位を操作するための施策ではなく、pardes、binet、AGI SDK、エンジニア採用に関する信頼できる情報源を増やす施策として考えてください。

## 7. 実装時の注意事項

- `main` ブランチへ直接コミット・直接プッシュしないでください
- `.env.local` などの秘密情報を変更・コミットしないでください
- 関係のないデザイン変更や大規模リファクタリングは避けてください
- 実装前に既存コードを読み、現在の実装方針に合わせてください
- 追加したSEO/AIO施策は、必ず根拠を説明できるようにしてください
- わからない用語や実装は、そのままコピーせず、意味を調べてから使ってください
- 被リンク獲得では、購入リンク、リンク集への大量登録、内容の薄い記事量産など、不自然な施策を行わないでください

## 8. 動作確認

Pull Requestを出す前に、少なくとも以下を実行してください。

```bash
npm run lint
npm run build
```

可能であれば、ローカルで表示確認も行ってください。

```bash
npm run dev
```

確認するURLの例:

- `http://localhost:3000/ja`
- `http://localhost:3000/en`
- `http://localhost:3000/sitemap.xml`
- `http://localhost:3000/robots.txt`
- `http://localhost:3000/llms.txt`

## 10. 口頭確認で説明してもらうこと

後日の確認では、以下を口頭で説明してください。

- どのようなSEO・AIO施策を実装したか
- その施策をどのファイルのどの部分に実装したか
- なぜその施策が必要だと判断したか
- pardesがどのような企業で、このHPが何を目的にしているか
- `binet`、AGI、SDK、開発者向け提供、エンジニア採用という目的を、どのようにSEO・AIOへ反映したか
- 既存実装をどう確認したか
- 自分で調べた情報源は何か
- 実装後にどのような確認を行ったか
- Google Search Console、被リンク、外部プロフィール整備など、サイト外で必要な施策は何か
- まだ改善できると考えている点は何か

説明では、抽象的に「SEOを改善しました」と言うのではなく、次のように具体的に話してください。

```text
app/[locale]/company/page.tsx の metadata を修正し、
会社概要ページのtitleとdescriptionを検索意図に合う表現に変更しました。
Google Search Centralのドキュメントを確認し、ページごとに固有のdescriptionを持たせることが重要だと判断しました。
```

## 11. 評価観点

評価では、実装量そのものよりも、次の観点を重視します。

- Gitの基本操作を正しい順序で行えているか
- Pull Requestで変更内容を読み手に伝えられているか
- SEO・AIOの施策に根拠があるか
- 既存コードの構成を理解したうえで実装しているか
- 変更範囲が課題目的に対して適切か
- lint / buildなどの基本的な確認を行っているか
- 口頭で「何を、どこに、なぜ実装したか」を説明できるか
- サイト内施策とサイト外施策を分けて理解できているか
- 被リンクや外部露出について、自然で信頼性のある施策を提案できているか
